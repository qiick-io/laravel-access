# Dependency register

Every runtime entry from the root `composer.json` `require` object is listed
below; `require-dev` is not. The register is reviewed at every release and in
every PR that changes `require`.

| Dependency                    | Version constraint | Why this minimum                                                                                                              | What we use                                                                                                                                                                                                                     | What we replace or extend and why                                                                                                                                                                          | Maintainer               | License | Known risk                                                                                                                                         | Exit plan within this package                                                                                          |
| ----------------------------- | ------------------ | ----------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------ | ------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `php`                         | `^8.3`             | Floor set at the scaffold (#1); the fleet standard for new packages. The CI matrix runs 8.3–8.5.                                | Language runtime: readonly classes and DTOs, enums, backed enums, `str_*` helpers, first-class callables across `src/`.                                                                                                          | Nothing to replace; platform requirement.                                                                                                                                                                   | PHP Group                | PHP-3.01 | None known.                                                                                                                                           | Not replaceable; the floor is raised deliberately per release.                                                          |
| `illuminate/auth`             | `^12.0 \|\| ^13.0` | The auth subsystem the package sits on: guard resolution (`Auth::shouldUse()` semantics) and the `auth` middleware its checks assume. Same major range as `illuminate/*`. | No `Illuminate\Auth\*` class is imported directly; the component guarantees the guard manager behind `Illuminate\Contracts\Auth\Factory` (resolved in `src/Laravel/AccessServiceProvider.php`, `ContainerActorResolver.php`, `SpatieTeamContext.php`) and the session guard the 2FA middleware (`src/Http/EnsureTwoFactorIsEnabled.php`) and actor resolution rely on. Whether `illuminate/contracts` alone would suffice is da verificare. | Nothing to replace; contracts declare the factory but only this component ships the guard implementation the package's auth assumptions need.                                                              | Laravel (Taylor Otwell)  | MIT     | Guard internals (session guard, `shouldUse`) are not a stability contract; the package touches them only through the `AuthFactory` contract.                                                                        | Bind actor resolution to the `Authenticatable` contract only and drop the component if a future Laravel exposes guards without it.          |
| `illuminate/contracts`        | `^12.0 \|\| ^13.0` | The package binds against contracts, not implementations; same major range as `illuminate/*`.                                   | `Illuminate\Contracts\Auth\Access\Gate`, `Auth\Authenticatable`, `Auth\Factory`, `Config\Repository`, `Container\Container`, `Events\Dispatcher`/`ShouldDispatchAfterCommit`, `Foundation\Application` across `src/`.          | Nothing to replace; depending on contracts keeps the authorization core testable and product-agnostic.                                                                                                     | Laravel (Taylor Otwell)  | MIT     | Contract interfaces can gain methods between majors; the `^12 \|\| ^13` range must be re-verified on each new major.                                                                                                  | Pin to concrete components only if a contract proves unstable; the usage is a handful of interfaces.                               |
