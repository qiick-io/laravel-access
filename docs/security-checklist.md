# Security checklist: properties and the tests that cover them

The binding design numbers the security properties the package must keep:
`AC1`–`AC12` (design §7), `AC13`–`AC17` (standards review §3.3), the fleet
checks `C7`, `C29` and `C30`, and `P1`–`P9` for principals (design §15.7).
Each row names the test that fails when the property breaks, so 1.0
checklist item 2 can be checked line by line. Test names are quoted from the
`it()` description, after the file in `tests/`. **Product** marks a property
only a product can prove (its own code or data); the fleet conformance
catalogue in `tests/Conformance` runs those checks in the product, and the
package ships the helper named in the row. **Partial** marks a property whose
package test covers only part of it.

Frozen behaviour in [public-api.md](public-api.md) and its tests: the
vocabulary ceiling (`Feature/Principals/PrincipalCeilingTest`,
`Feature/EnsureUserHasPermissionTest` › gives an API actor of a super-admin
owner the permission vocabulary within its scopes), the Gate's no-arguments
rule (`Unit/GateBeforeTest` › does not grant a permission when arguments are
present even without a Policy), tombstones
(`Feature/Principals/PrincipalDirectoryTest` › never overwrites a
deactivated principal, so an erased tombstone stays erased (review B3); ›
preserves the membership tombstone when a product soft-deletes and restores
a user) and the connection-name boot check (`Feature/BootChecksPhpUnitTest`
› fails when a database connection reports a name other than its key).
